# Нейросети и голос

## Первый ответ с Windows 10

1. Откройте профиль Станции и раздел **Нейросети → Провайдер и чат**. Колонку можно подключить позднее.
2. Выберите **DeepSeek**. Базовый адрес — **https://api.deepseek.com**. Вставьте ключ своего API-аккаунта и нажмите **Сохранить ключ**. После сохранения поле очищается, а Windows шифрует ключ для текущего пользователя. Ключи разделены по профилю, провайдеру и базе API.
3. Нажмите **Обновить каталог моделей**. Выберите один из полученных ID. Если совместимый сервер не публикует каталог, введите точное имя модели вручную и нажмите **Сохранить настройки**.
4. Введите, например, «Ответь одним словом, какого цвета трава?» и нажмите **Отправить запрос**. Ответ покажет модель и время ожидания. За запрос провайдер может списать средства. Встроенный клиент DeepSeek ограничивает длину ответа 1 024 токенами и отключает дополнительный режим размышления. Список моделей обновляется без пробной генерации. [Каталог](https://api-docs.deepseek.com/api/list-models/) · [Формат ответа](https://api-docs.deepseek.com/api/create-chat-completion/)
5. При продолжении разговора сервер получает реплики открытого диалога. **Остановить** прерывает ожидание Windows, уже отправленный запрос мог быть обработан. Повторной отправки после обрыва нет. **Новый диалог** очищает переписку. Программа держит её только в памяти.

Для своего облачного сервера добавьте провайдера или выберите совместимый профиль. Используйте конечный HTTPS-адрес API, исключив путь конкретного вызова, логин, секрет и строку параметров. Программа самостоятельно добавляет путь models или chat/completions. Проверяется TLS-сертификат, автоматические редиректы отключены. Встроенные профили Ollama и LM Studio указывают на типовые адреса localhost. Запустите совместимый сервер и модель в его приложении, сверьте порт и видимость модели. Локальный HTTP поддерживается без ключа на loopback или частном IP. Для ключа используйте HTTPS с доверенным сертификатом. Выбор другого сервера очищает контекст чата. API-ключ и чат исключены из экспорта профиля.

| Сообщение | Что проверить |
| --- | --- |
| HTTP 401/403 | Правильный ли ключ сохранён для указанного адреса, разрешён ли доступ к модели. |
| HTTP 402, недостаточно средств или квоты | Баланс API-аккаунта у провайдера. |
| HTTP 404/405 для models | Введите модель вручную, проверьте относительный путь базы. |
| HTTP 400/404/422 при генерации | Сверьте точный ID и поддерживает ли сервер Chat Completions. |
| HTTP 429 | Дождитесь освобождения лимита. |
| TLS, сеть, ожидание, некорректный формат | Проверьте имя и сертификат сервера, системные часы, путь API, его доступность. Перед повтором платного запроса проверьте расход у провайдера. |

## Голос после прошивки

Вкладка **Голос на Станции** хранит выбранный план. Для каждого варианта на экране указаны владелец микрофона и динамика, необходимые серверы, проверка и возврат к штатной Алисе.

| Режим | Что остаётся включено |
| --- | --- |
| Штатная Алиса | Станция и интернет. |
| Внешняя модель через Quasar Bridge | Станция, интернет для речи Яндекса, размещённый на Станции или отдельном сервере мост и доступная модель. При локальной LLM на Windows-ПК этот ПК работает во время запроса. |
| Нативный ChatGPT Voice | После установки на совместимую станцию и отдельного входа в ChatGPT в браузере — Станция и интернет. Смена чата выполняется штатными фразами Alisa Voice. |
| ChatGPT через браузерный мост | Станция, Linux-хост с Chromium и PipeWire/PulseAudio и интернет. |
| Home Assistant Assist | Станция, сервер HA с Assist, распознавание, диалоговый агент и синтез. Во время работы Pulsar останавливает штатный Quasar. На полностью локальной системе отдельно испытайте разговор с отключённым внешним интернетом. |
| quasard, v3rt3p | Отдельный постоянно работающий сервер с ресурсами и зависимостями выбранного проекта. Конфигурации со сторонними облаками требуют интернета. Совместимость с 00026 требует проверки. |

### Подготовить Quasar Bridge

На Windows сохраните поставщика и ID модели. Выберите **Внешняя модель через Quasar Bridge**, размещение моста, начало обращения и правило маршрутизации. Поле **База API с хоста моста** позволяет указать адрес, видимый устройству. Для DeepSeek обычно используется https://api.deepseek.com/v1. Для модели на домашнем ПК укажите его доступный в сети адрес. На Станции localhost указывает на саму Станцию.

Нажмите **Сохранить фрагмент настройки моста**. JSON содержит параметры Chat Completions и выбранный набор правил для версии 0.7.6. В варианте «Только по обращению» модель получает вопросы с заданным началом после «Алиса», остальные запросы идут в Яндекс. В варианте классификации мост решает маршрут остальных запросов. Перед включением классификации учитывайте передачу текста фраз поставщику модели. Сохранённый фрагмент содержит целый массив routing.rules. Если у вас есть домашние сценарии, вручную объедините правила, сохранив нужную очерёдность. Первое совпадение определяет маршрут. [Руководство 0.7.6](https://github.com/skrashevich/quasar-bridge/blob/v0.7.6/docs/guide.md)

До установки сохраните снаружи колонки действующие quasar.cfg, config.json, runtime.env и значения uniProxyUrl/uniProxyQuicUrl. Секретный файл храните отдельно с ограниченным доступом. На самой колонке подтвердите плату, ABI и прошивку. Сборка ARMv7 существует, однако для Лайт 2 с часами YNDX-00026 эта цепочка требует отдельного испытания. Установку выполняют по инструкции зафиксированной версии. Для shell-установщика подходят указанные автором Linux/macOS/WSL, сам Windows-клиент работает нативно. Включите настройки только после проверки совместимости. Ключ QUASAR_LLM_API_KEY для runtime.env задаётся владельцем на хосте моста. Настройки окружения могут переопределять JSON.

Для недавно настроенного моста на Станции сначала сверьте в его конфигурации адрес, выбранную модель и настоящий режим. Подключитесь в разделе **Станция**, затем нажмите **Проверить API с хоста моста**. Действие требует согласия. Мост может проверить до десяти вариантов параметров, выполняя обычные и JSON-запросы. Результат описывает собственные настройки моста в момент проверки. Для моста, расположенного на Linux-сервере, откройте его установленную версию 0.7.6 в окружении службы с тем же файлом конфигурации и секретами. Следующие команды запускает владелец на хосте. Первая команда запрашивает каталог. Вторая может расходовать средства.

~~~sh
quasar-bridge -config config.json -list-models
quasar-bridge -config config.json -probe-llm-compat
~~~

Проверка «у Станции» завершается только после речи. Скажите «Алиса, спроси нейросеть, сколько будет три плюс восемь?». Проверьте распознанный текст и маршрут llm в диагностике моста и услышьте «одиннадцать». Проверьте обычный таймер. Для возврата остановите мост, восстановите оба сохранённых адреса uniProxy и штатную службу по руководству проекта. Проверьте обычный диалог после перезагрузки. [Порядок развёртывания и откат](https://github.com/skrashevich/quasar-bridge/blob/v0.7.6/docs/guide.md)

Для Alisa Voice нативный отчёт о Windows относится к Windows 11, а в описанной проверке Linux использовалась Лайт 2 без часов YNDX-00028. Версия 0.3.10 поддерживает отдельные профили, но не содержит нового аппаратного прогона на Windows. Для Pulsar опубликован живой тест с Лайт 2 (Plum) и прошивкой с окончанием .133. Номер розничной модели в этой проверке не указан. Для своего экземпляра проверьте обе стороны диалога, работу кнопки микрофона, нормальный возврат Алисы и автозапуск.
