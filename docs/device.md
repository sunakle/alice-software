# Подключение своей Станции Лайт 2

## Что получить у друга

Узнайте адрес колонки в домашней сети, тип доступа и порт. Попросите проверить доступ после перезагрузки, восстановить обычный DNS роутера и проверить штатный ответ Алисы. Для SSH передайте другу **публичный** ключ владельца Windows. Друг добавит его в разрешённые ключи на Станции. Приватная половина остаётся на вашем ПК. По отдельному каналу попросите отпечаток публичного **ключа сервера** (SHA256). Ключ сервера опознаёт колонку, а ключ пользователя разрешает вход.

Попросите исходные копии CA, конфигурации запуска и файлов OTA, которые менялись во время получения доступа. Храните их вне колонки. При обычном заводском сбросе очищается /data. Первичные операции с сертификатами, разделами и загрузчиком выполняет человек, занимающийся подготовкой. Ваш Windows-ПК после передачи работает через домашнюю сеть.

## Первое подключение

1. Откройте «Станция». Введите один адрес и выберите SSH (обычно 2222) либо ADB (обычно 5555). Укажите реальный порт друга. Программа проверяет только этот узел и порт. Если у DNS-имени несколько адресов, программа берёт первый IPv4, а при отсутствии IPv4 — IPv6. Можно ввести IP явно.
2. Для SSH нужен Windows OpenSSH Client, включая ssh-keyscan. Нажмите «Ключ SSH…» или используйте стандартный ключ Windows. Ключ с парольной фразой предварительно разблокируйте в доверенном ssh-agent вашей учётной записи. Программа не собирает пароль и не показывает диалог SSH в консоли. Для ADB распакуйте официальные Android SDK Platform Tools, выберите adb.exe. Запуск ADB может запустить стандартный локальный сервер этого клиента.
3. Нажмите «Проверить и подключить». Панель показывает результат разрешения адреса, время ответа TCP, аутентификацию и затем отдельную инвентаризацию. При первом SSH сверьте отпечаток с присланным другом. Если ключ изменился, вход остановится. После проверки причины можно создать новый локальный профиль и снова сверить отпечаток. ADB использует конкретный сетевой идентификатор адрес:порт. При offline/unauthorized проверяйте выбранную станцию, даже если к ПК подключён доступный по USB телефон.
4. Сравните измеренные плату, прошивку и SKU со своей колонкой. На фото владельца YNDX-00026 с часами. У YNDX-00028 часов нет. Если прошивка не раскрывает SKU, программа сообщает «нет данных». Заранее введённое имя профиля не заменяет идентификацию. Для различения экземпляров используются хеш доступного системного идентификатора и признаки платы. Идентификатор не включается в выгружаемый отчёт.
5. Проверьте наличие Quasar, ALSA, socat, локального IPC, версии ELF и свободного места. Изменение платы, привязки или сборки требует новой инвентаризации. Кнопка отмены доступна во время сетевой операции. Истинная аппаратная проба всегда требует самой станции. Сохраняемые результаты содержат время UTC и выбранный транспорт.

## Голос, свет и звук

«Сказать текст» передаёт текст по SSH в существующую голосовую сессию Quasar, которая использует облачный синтез Яндекса. Нужны домашняя сеть, включённые колонка и ПК, интернет у колонки и её действующая авторизация. Сначала проверьте обычный вопрос к штатной Алисе, остановите сторонний голосовой режим. Кнопка требует признаков Plum, root, 32-битного maind, найденного socat, слушающего API и известной сборки 0.369.1.50.4794654278.20261021.133. Именно эту сборку исследовали на 00028. Программа подписывается на события начала и окончания, затем отдельно спрашивает, слышали ли вы введённую фразу. Подписка не привязана к ID реплики. Если эфир занят, дождитесь тишины. При тайм-ауте автоматического повтора нет.

«Короткий тон» подаёт тихий сигнал через GStreamer и ALSA. «Файл WAV…» передаёт ваш RIFF/WAVE до 1 МиБ по SSH во временный файл /tmp, проверяет SHA-256, воспроизводит до 12 секунд и удаляет файл. Для радио введите прямую публичную HTTPS-ссылку на аудиопоток без токенов и параметров, затем нажмите «Радио 12 с». Станции нужны работающий timeout и подходящие сетевые модули/кодеки GStreamer. При переподключении не повторяйте звук, пока не выясните, завершилась ли первая попытка. При аварийном отключении питания временный файл не является постоянным модулем. Громкость определяется текущим звуковым трактом колонки.

«Вспышка 2 с» — аппаратный тест верхнего индикатора. Остановите программы, использующие верхний свет, оставьте микрофоны включёнными и дождитесь покоя. Программа считывает яркость и штатный триггер девяти каналов; пишет снимок в локальные копии. Рабочий процесс на самой колонке кратко управляет кольцом, проверяет физический mute, возвращает яркость и затем триггеры. При неизвестном состоянии mute, несовпадении сборки, неполном наборе каналов или изменении снимка остановится. Фоновый процесс продолжит откат при потере связи с Windows. Передние часы настраиваются штатно. Компьютерный макет в каталоге не записывает сегменты на устройство.

Физическая 00026 с конкретной прошивкой нужна для проверки слышимости, свечения и корректности восстановления штатного режима. После каждого теста по возможности отдельно проверьте обычную Алису, физический mute и поведение после перезагрузки. Встроенное приложение не устанавливает драйверы микрофона Windows.

## Диагностика и возврат

Панель «Восстановление» показывает текущие измерения и отличие от прошлого сохранённого снимка. В обезличенном экспорте остаются параметры CPU, типа ELF, ядра, свободной памяти, аппаратных каналов и известных служб. Содержимое конфигов, сетевые адреса и необработанные строки журналов исключены. Если известный журнал доступен, отображаются только число последних просмотренных строк (не более 100) и число сообщений с error/fatal. Поиск и список пакетов yse/opkg работают с уже настроенным на колонке менеджером и его текущими списками. Подключение через ADB позволяет читать диагностику; операции с конфигами и голосом используют SSH.

Для копирования выберите существующий /data/opt/etc/yse/sources (реестр пакетов) либо /system/vendor/quasar/launch.json (запуск). При подтверждённой привязке и читаемом обычном файле размером до 256 КиБ программа сохраняет содержимое, SHA-256, права, UID/GID и отпечаток экземпляра/сборки. Нужны доступные readlink, stat, base64 и sha256sum. Файл .stationbak хранится на ПК в папке station-backups профиля, зашифрован Windows DPAPI для текущего пользователя и профиля Windows. Эти копии дополняют независимый архив исходников, переданный другом. Если планируете переустановку Windows, отдельно сохраните исходники с доступным владельцу способом расшифровки.

«Сравнить с копией…» повторно читает текущее состояние и показывает хеши, размеры и права. «Вернуть реестр yse…» предназначено для восстановления **существующего** /data/opt/etc/yse/sources. Перед заменой показывается план, запрашивается согласие и сохраняется новая копия текущего файла. Перед записью перепроверяются хеш и права. Подмена выполняется в том же каталоге через временный файл, с последующим контролем хеша, прав и владельца. Символические ссылки и другая сборка не допускаются. При обрыве заново подключитесь и сравните файл с обеими копиями. Не удаляйте блокировку изменения, пока не подтвердили, что на колонке не продолжается операция.

Системный launch.json доступен для создания резервной копии и сравнения. Для восстановления повреждённой прошивки используйте исходные данные своего экземпляра и инструкцию вики. При потере SSH попробуйте сеть и адрес, затем доступ по ADB. Сброс в заводское состояние удаляет /data и не гарантирует возврат изменений системного раздела.
