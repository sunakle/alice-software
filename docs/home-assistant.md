# Голосовая команда для домашнего ПК

Этот способ подключает агент к Home Assistant (HA) без входящего порта Windows. ПК, HA и голосовой спутник должны работать. Агент опрашивает один выбранный домашний сервер по HTTPS раз в две секунды. Для штатной Алисы без настроенного входа в Assist этот маршрут ещё не подключён.

1. В «Команды ПК» проверь действие с ID `chrome`. Если путь пуст, выбери установленный chrome.exe. Нажми «Сохранить и разрешить». Проверь фразу кнопкой «Выполнить на этом ПК».
2. Открой вкладку «Подключение Home Assistant» и скопируй «Адресат команды». Открой в текстовом редакторе файлы `home-assistant-package.yaml` и `home-assistant-sentences.yaml` рядом с этой инструкцией. В пакете замени только `ЗАМЕНИТЕ_НА_АДРЕСАТ_ИЗ_ПРОГРАММЫ` на скопированный адресат. Это идентификатор назначения. Секретным остаётся токен HA.
3. Скопируй пакет в `packages/stantsiya_desk.yaml`, а второй файл — в `custom_sentences/ru/stantsiya_desk.yaml` внутри конфигурации HA. Для установки пакетов нужен параметр `packages: !include_dir_named packages` внутри существующего раздела `homeassistant` файла configuration.yaml. Объедини с уже имеющимися настройками без перезаписи. Выполни проверку конфигурации в HA и перезапусти его. Если одноимённые помощники уже существуют, сначала исключи конфликт.
4. В HA создай отдельный долгоживущий токен для Windows в своём профиле → безопасность. У аккаунта должен быть доступ к чтению и изменению двух помощников. Не вставляй токен в YAML. На Windows введи HTTPS-адрес HA, выбери свой Ethernet или Wi-Fi, введи токен и нажми «Проверить и подключить». Агент перед каждым запросом проверяет, что адреса сервера локальные и маршрут Windows проходит через выбранный интерфейс. К HTTPS-клиенту передаётся уже проверенный числовой IP, а сертификат должен соответствовать введённому имени. Для числового адреса нужен сертификат с этим IP в SAN. Перенаправления и системный прокси отключены. Для своей CA установи доверие к её проверенному корневому сертификату отдельно. При смене сети перепроверь настройку. Фактическую сетевую трассу определяет Windows.
5. В инструментах разработчика HA запусти действие `script.stantsiya_desk_chrome`. Агент должен запустить Chrome. В журнале Windows появится результат вызова ОС, а в `input_text.stantsiya_desk_reply` — ID запроса с окончанием `|ok`. Затем введи в Assist «открой хром на компьютере». После текстового испытания произнеси эту фразу в настроенный спутник HA (например, совместимую Станцию с Pulsar) и проверь окно программы.
6. Для обратной проверки отзови разрешение на действие или заверши агент. HA должен сообщить об отказе или об отсутствии подтверждения. В настройках агента «Отозвать доступ» останавливает опрос, удаляет локальный токен и заменяет адресат. Для полного отзыва удали токен со стороны HA. Если больше не нужны голосовые команды, убери добавленные YAML и перезагрузи конфигурацию.

Пока компьютер активен, Windows должна разрешать запуск программы в сеансе вошедшего пользователя. Нажми флажок автозапуска, если агент нужен после входа. Перед выключением ПК завершённость операции проверяй по ответу. При отсутствии ответа исход неизвестен: окно могло открыться до обрыва сети. Пока запрос ожидает подтверждения, образец ставит следующие вызовы в очередь. Произвольная перезапись `input_text.stantsiya_desk_command` в обход сценария может заменить необработанное сообщение. Изменение времени на ПК или HA может отклонять запросы: предел давности 30 секунд, допуск ухода времени в будущее 5 секунд.

Агент сохраняет событие перед выполнением и повторяет неподтверждённый ответ после перезапуска без повторного запуска команды. Ответ `|unknown` означает, что агент завершился до сохранения результата и состояние нужно проверить на ПК. Ответы привязаны к адресу того сервера, от которого пришла команда. При отзыве доступа очередь удаляется.

Для ещё одного действия добавь разрешённую цель с другим ID на ПК и используй этот ID в сценарии HA. Сетевой запрос содержит только назначение, ID события, время и ID действия. Аргументы командной строки из HA или от языковой модели не исполняются. Этот канал использует REST HA, штатные helpers и локальный список разрешений. Внешний навык «ПК Мост» имеет собственный клиент и отдельную привязку.

Источники — [REST API HA](https://developers.home-assistant.io/docs/api/rest/), [помощник input_text](https://www.home-assistant.io/integrations/input_text/), [Intent Script](https://www.home-assistant.io/integrations/intent_script/), [свои предложения для Assist](https://www.home-assistant.io/voice_control/custom_sentences/).
