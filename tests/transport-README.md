# Локальный стенд SSH, ADB и восстановления

Стенд запускает транспорт непосредственно из собранного StantsiyaDesk.exe. Можно указать файл программы или переносимый ZIP сборки. Для SSH используется штатный клиент Windows и настоящий временный сервер Paramiko на 127.0.0.1 со случайным портом и новыми ключами. Службы Windows и firewall не настраиваются. Тестовый сервер принимает только сгенерированный клиентский ключ. После испытания он завершает работу.

Запусти из обычного сеанса своего пользователя Windows с загруженным профилем. Нужны Python 3.12 x64 с тестовой библиотекой Paramiko 3.5.1, Windows OpenSSH Client, Git for Windows с sh.exe и установленный .NET Framework с C#-компилятором. Интернет нужен только для предварительного получения тестовых зависимостей. Проще выделить библиотеке временный каталог.

```powershell
$testLib = Join-Path $env:TEMP 'StantsiyaDesk-test-lib'
python -m pip install --target $testLib paramiko==3.5.1
python tests/transport-loopback.py dist/StantsiyaDesk-portable-x64.zip --deps $testLib
```

Если Paramiko уже установлена в отдельном тестовом окружении Python, параметр `--deps` не требуется. Для нестандартной установки Git укажи `--shell` с полным путём к его usr/bin/sh.exe. Код возврата 0 означает завершение всех проверок. Пакеты Python и Git для обычной работы Пульта Станции не нужны.

**Что проверяется.**

* SSH с двумя независимо созданными серверными ключами и двумя клиентскими ключами. Проверяются отказ доверять неизвестному серверу, сравнение SHA-256, вход подходящим ключом, отклонение неверного ключа и смены ключа сервера, тайм-аут при незавершённой команде и отказ закрытого TCP-порта.
* Реальная передача содержимого файла по SSH, проверка целостности и сохранение/чтение резервной копии с DPAPI CurrentUser. Подготовленный стендом экземпляр метаданных представляет тестовую плату. Единственный фиксированный путь файла yse во входящем скрипте переадресуется во временный каталог. Остальной текст сценария приложения исполняет sh на этом ПК. Для NTFS/Cygwin на протяжении сеанса задан одинаковый umask, чтобы синтетические режимы доступа были сопоставимы между соединениями.
* Сервер обрывает чтение копии посередине, закрывает соединение перед началом замены файла и отдельно после выполнения замены до отправки кода результата. Проверяется содержимое настоящего временного файла до и после каждого случая. После потери подтверждения приложение повторно читает состояние и может завершить повторную операцию без второй замены.
* Для ADB компилируется отдельный имитатор командного клиента. Он возвращает целевую сетевую станцию и постороннее устройство. Тест проверяет фактические аргументы дочернего процесса, выбор нужного serial, обработку состояний offline, unauthorized и пропажи целевого serial.

Этот прогон не воспроизводит аппаратные драйверы, аудио, электропитание, flash, настоящий ADB-демон или перезагрузку колонки. Для проверки на устройстве используй пользовательскую инструкцию и отдельно регистрируй подтверждённые модель, прошивку и операцию.
